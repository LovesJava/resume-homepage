# 个人主页滚动动效设计

## 目标

增强个人主页在首屏加载和向下滚动时的视觉反馈，让动画清晰可感知，但保持专业、克制，不影响简历内容阅读。

## 方案选择

继续使用页面现有的原生 `IntersectionObserver`，不引入第三方动画库。

选择该方案的原因：

- 与现有页面结构和脚本一致，改动范围小。
- 现代浏览器兼容性和运行性能良好。
- 不增加网络依赖，不影响 GitHub Pages 静态部署。
- 可以完整控制动画强度、错峰节奏和无障碍降级。

不采用的方案：

- CSS 滚动时间轴：部分浏览器兼容性不足。
- AOS、GSAP 等动画库：对当前单页简历而言依赖和复杂度过高。

## 动效行为

### 首屏

- 页面首次加载时，职业标签、主标题、个人介绍、操作按钮、职业数据和形象照依次进入。
- 使用淡入、向上位移和极轻微缩放的组合。
- 动画仅在首次加载时播放一次。

### 滚动区块

- 区块标题进入视口时，从下方约 40 像素处淡入。
- 关于我、项目、经历、能力和联系区域在进入视口约 12% 至 15% 时触发。
- 动画持续时间约 700 毫秒，使用平滑减速曲线。

### 分组错峰

- 能力卡片、项目卡片、经历条目和技能分组按 DOM 顺序依次出现。
- 相邻元素之间使用约 90 毫秒延迟。
- 卡片使用约 28 至 32 像素位移和极轻微缩放，避免夸张弹跳。
- 每个元素显示后停止观察，向上或向下重复滚动时不重新播放。

### 响应式表现

- 桌面端使用完整位移和错峰节奏。
- 手机端缩短位移和动画时长，避免小屏滚动时动画拖沓。

## 技术结构

- CSS 使用统一的揭示基础类、可见状态类和 CSS 自定义属性控制延迟。
- JavaScript 为不同分组按索引写入延迟，并通过单个 `IntersectionObserver` 切换可见状态。
- 首屏元素使用独立的加载状态类，避免与滚动观察器互相影响。
- 保留现有导航栏区块高亮观察器，两套观察逻辑职责分离。

## 降级与无障碍

- 当系统启用 `prefers-reduced-motion: reduce` 时，所有内容立即显示，不执行位移、缩放或错峰动画。
- 浏览器不支持 `IntersectionObserver` 时，所有目标立即进入可见状态。
- JavaScript 未执行时页面保持可读，不允许内容永久隐藏。
- 动画不改变 DOM 顺序、焦点顺序或语义结构。

## 测试与验收

自动检查：

- 首屏和滚动目标拥有正确的动画标记。
- 分组元素生成递增的错峰延迟。
- 元素进入视口后获得可见状态。
- 不支持观察器时内容立即显示。
- 减少动态效果规则可以取消动画。

浏览器检查：

- 桌面尺寸首次加载时首屏动画正常。
- 向下滚动时区块标题和卡片依次进入。
- 动画播放结束后文字和照片清晰可见。
- 手机尺寸下无横向滚动，动画节奏不拖沓。
- 控制台无脚本错误。

线上验收：

- 将实现提交并推送至 `main`。
- GitHub Pages 公网首页返回 HTTP 200。
- 线上 HTML 与本地提交一致。
- 形象照返回 HTTP 200 并正常渲染。
